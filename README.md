# Operza website

The public website for **Operza**, the company, and its products:

- **Operza Shift**, manufacturing operations and accounting software, live at
  **https://app.operza.in** and built in a separate repository. Its plans keep
  their own names in the app: Operza Factory, Operza Books, Operza Complete.
- **Operza Linspace**, for construction, **in development and not launched**.

Live at **https://www.operza.in**. The multi-product site in this repository
was built as one release candidate and reaches production only after the
Founder's visual approval; see `CLAUDE.md` for the full record and the open
decisions.

> **Product truth lives in `operza-app`, not here.** Before writing or changing
> any customer-facing claim on this site, check it against
> [`kartikvagh12-bot/operza-app`](https://github.com/kartikvagh12-bot/operza-app).
> This repository markets the product; it is not a source of truth about what
> the product does.

- **Operza** is the public brand. The legal name, Operza Technologies Private
  Limited, appears only in the footer's legal line and the Organization's
  `legalName`.
- A conversational assistant ("Ask anything about Operza...") is planned. It
  will only be added once it works; no provider, model or policy is approved,
  and no placeholder input is shown.

## Operza Shift and the Health Check

The Operza Shift page (`/shift`, the homepage until the multi-product
cutover) is built around the current product (Factory, Books and Complete, costing and margin, the books and
the TallyPrime export, the operational record), and `/health-check` has been
refreshed to match.

The Health Check remains **factory-operations scoped**: it asks how visible and
how well recorded materials, production and finished goods are, and nothing
about the books. Its **scoring model is frozen**: the same eight question ids in
the same order, the same option scores and flags by position, the same
`MAX_SCORE` and the same 85 / 60 band thresholds. Only the wording changed,
because there is no evidence base for recalibrating the numbers.

**No page shows the app.** Real screenshots were removed on
founder review: they read as blurry and static, and even sample captures put
literal product data on a marketing page and made it feel like documentation.

The product story is now **website-native interactive examples** in
`components/demos/`. Each is a small interface that borrows Operza's visual
language and lets a visitor click a control and watch a business result change:
material in and units out, a bill and a payment, a dispatch that moves the floor
and the books together, and a material cost that moves the margin.

They are local React state only. No fetch, no persistence, no product code, and
no customer or sample-workspace data. Every value is invented for the website
and each panel is labelled **Interactive example**.

## Stack

- Next.js 14 (App Router) with TypeScript
- Tailwind CSS 3
- `@supabase/supabase-js` for the lead form only
- Deployed on Vercel

Note that `operza-app` is on Next 16 / React 19 / Tailwind 4. The two share a
brand palette and typeface but not a design-token system, so components are not
portable between them.

Light and deep sections alternate deliberately. `.section-deep`, `.h-deep`,
`.btn-invert` and `.bg-grid-invert` in `app/globals.css` carry that treatment.

Shared pieces:

- `lib/site.ts` is the single source for URLs, contact details and nav links.
  Every "sign in" link resolves through `SITE.app`, and every "Book a demo"
  through `DEMO_HREF` (`/shift#contact`). It also holds `PRODUCTS`, the
  registry of Operza products (Operza Shift and Operza Linspace) with each
  one's path, whether its page is live, its status and its industry. The
  navbar's Products menu, the footer and the homepage index all read it.
  Marketing identity only: plans and capabilities stay in `operza-app`.
- `components/art/` holds the inline-SVG and HTML drawings (`TangleToOrder`,
  `ShiftFlow`, `PlanDrawing`). They draw once on load (`.draw` and `.appear`
  in `app/globals.css`) and appear finished under reduced motion.
- `lib/faq.ts` is the single source for the FAQ. The visible accordion and the
  `FAQPage` structured data both read it, so the two cannot drift.
- `components/demos/` holds the interactive examples and their shared parts.
  Local state only: no fetch, no persistence, no product code.
- `lib/og-card.tsx` renders the social card shared by both image routes.
- `app/globals.css` holds the `@layer components` primitives
  (`.container-page`, `.btn-primary`, `.section`, `.eyebrow`, `.h-section`,
  `.p-section`, `.surface`).
- `tailwind.config.ts` carries the brand palette, which matches `operza-app`.

## Environment variables

The contact form writes leads into a Supabase table. Two variables are needed
locally and on Vercel (Production, Preview and Development):

```
NEXT_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon publishable key>
```

Copy `.env.local.example` to `.env.local` for local development.

## The `demo_requests` dependency

`components/Contact.tsx` inserts leads into the Supabase table
`demo_requests`. Two things are worth knowing:

1. The table lives in the Supabase project shared with `operza-app`
   (`kragnxmsspfaxiejyqgm`).
2. **Its schema is defined in the `Inventory_tracker` repository**
   (`supabase/migrations/003_demo_requests.sql`), which is the retired
   Streamlit app. Nothing in `operza-app` defines this table.

That is an open maintenance concern: the lead form depends on a table whose
migration lives in a repository that is being wound down. If the table is ever
dropped during that teardown, the form fails silently and the only signal is a
`console.error` in the browser. Moving the table definition into `operza-app`,
or otherwise taking ownership of it, is tracked separately and is deliberately
not part of the marketing refresh.

## Checks

```bash
npm run build            # type-checks and builds
npm run lint
npm run test:marketing   # both static guards
```

Two dependency-free static guards, neither of which builds, renders or makes
network calls:

`test:marketing-foundation` covers each page's metadata, the structured data
on each page, the sitemap, the social card per route, the navbar, the footer
and the brand-versus-legal-name split. It fails if a free-price offer returns to the
structured data, if `#fragment` URLs come back to the sitemap, if the retired
Streamlit constant reappears, if a route advertises a large-image card with
no image behind it, if the product registry claims a page that does not exist,
or if any internal link (including a link or sitemap entry for a product page
that is not live yet) points at a page or public asset that does not exist.

`test:marketing-copy` covers every page (`/`, `/shift`, `/linspace`), every
component (collected recursively) **and the Health Check**. It extracts
customer-visible strings first, with comments stripped, and judges only those,
so an import path or a code comment is invisible to it by construction. It
fails on an em dash in rendered prose, on retired product vocabulary, on a
claim outside the locked boundaries, on a capability-seam violation, and on an
anchor that does not resolve on the page it points at. Section M pins the
company homepage (the Founder's headline, no fake assistant input, no second
lead form, company-only structured data). Section N holds Operza Linspace to
"in development": no dates, prices, launch or sign-up language, no form,
`noindex`, no structured data.

Known limit: the string extractor reads text between tags, so a sentence that
follows a JSX expression (`{NAME} is ...`) is not extracted. Section N also
judges the comment-stripped source text of the Linspace files to close that
gap where it matters most.

The em-dash rule is expressed as a rule rather than a whitelist: a string whose
entire value is the glyph is an empty-value table placeholder and is exempt,
while an em dash inside a sentence is prose and is not.

### Lead-form smoke test

`.smoketest.mjs` verifies the anon-key policy on `demo_requests`: an insert
should succeed, and select, update and delete should all be refused. It inserts
one row per run.

```bash
URL=<supabase url> KEY=<anon key> node .smoketest.mjs
```

It is not wired into `package.json`, is not part of CI, and should only be run
deliberately.

## Deployment

Vercel, with the Next.js preset detected automatically. `next.config.mjs`
carries one rule: a permanent host-scoped redirect from the legacy
`operza.vercel.app` domain to `https://www.operza.in`. Production custom domains
are untouched by it.

## Copy rules

Customer-facing copy on this site follows the vocabulary shipped in
`operza-app`:

**Brand**: black and white with one restrained red accent. The red is
`#f31820`, sampled from `public/operza-logo.png`, and is the `brand` scale in
`tailwind.config.ts`. Use it for the primary emphasis, an active tab, a selected
state and small rules or dots. It is not an error colour, and it is not the page
background.

- **material**, never "part"
- **finished goods**, never "FG"
- **average cost**, never "WAC"
- **Cost changes**, never "cost intelligence"
- **workspace code**, never "slug"
- **plan**, never "suite" or "capabilities"
- no database, transaction or RPC vocabulary in anything a visitor reads

Marketing prose contains **zero em dashes** (U+2014). The only exceptions are
the empty-value glyphs inside the interactive demo's tables, which are data
placeholders rather than prose.

Claim boundaries any new copy must respect: Factory has no accounting, Books has
no stock or production, the connected behaviour belongs to Operza Complete,
margin is gross margin against manufacturing cost captured at dispatch, Tally is
export only, and there are no pricing, compliance, certification or
plan-switching claims.
